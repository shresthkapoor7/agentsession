# agentsession API

FastAPI control plane for publishing and retrieving client-encrypted transcript
blobs. Supabase provides private object storage and Postgres; plaintext transcript
content and browser encryption keys never reach this service.

## Local setup

1. Copy `.env.example` to `.env` (a local `.env` with the project URL already
   exists in this checkout).
2. Add the Supabase service-role key, a random capability hash pepper, and a
   random internal cleanup token. Never expose these values to the frontend.
3. From this directory, run `uv sync` and then
   `uv run uvicorn app.main:app --reload --no-access-log`.

Generate the two application secrets with `openssl rand -hex 32`. Railway should
receive the same settings as environment variables and use `/health` for health
checks.

The Supabase bucket is private. Browser uploads use a one-object signed upload
URL generated by this API. Supabase currently fixes signed upload URL validity at
two hours; the API independently expires publish intents after ten minutes.

Access logs are disabled because capability tokens live in endpoint paths. Add
request metrics using route templates, never raw request URLs.

## Publish contract

`POST /v1/publish-intents` accepts only reviewed metadata and the final encrypted
blob size. It returns a one-object upload URL plus view and management
capabilities. The browser keeps those capabilities, uploads the ciphertext with
the returned method and headers, then echoes both capabilities to
`POST /v1/publish-intents/{id}/complete`. Completion verifies the stored object
size before making the share visible.

The completion response contains share and management URLs without an encryption
key. The frontend appends its locally generated content key as a URL fragment
(`#k=...`); fragments must never be sent in an API body or query string.

Public retrieval uses `GET /v1/shares/{view_token}`. Password shares use
`POST /v1/shares/{view_token}/unlock`. Revocation uses
`POST /v1/manage/{manage_token}/revoke`, and the Railway cron calls
`POST /v1/internal/cleanup-expired` with `X-Internal-Token`.

## Railway services

Use `backend/` as the root directory for the web service; `railway.json` supplies
its start command and health check. Create a second Railway service from the same
directory for cleanup, set its start command to
`uv run python -m app.cleanup_job`, and schedule it hourly. Both services need the
same `INTERNAL_CLEANUP_TOKEN`; the cleanup service also needs the web service's
`BACKEND_PUBLIC_URL`. Only the web service needs the Supabase service-role key
and capability pepper.
